## 执行过程

使用仓库现有 VM 构建→压缩导入 NAS→固定版本 Compose 通道，分阶段执行，避免停机后重复构建/传输：

```bash
COMPOSE_DIR=<protected-config> \
BUILD_DIR=/home/lvziw/.cache/igngbot-build/yunying-v4-579e33f22617 \
V4_VERSION=579e33f22617 bash deploy/deploy-v4-nas.sh images
# 停止 bot/yunying，备份与校验完成后：
COMPOSE_DIR=<protected-config> V4_VERSION=579e33f22617 bash deploy/deploy-v4-nas.sh sync
# 以下在 NAS 的现役 Compose 根运行；与 up 的迁移/启动阶段一致：
docker compose --env-file .env --env-file .env.v4 -f docker-compose.yml -f docker-compose.v4.yml run -T --rm --no-deps --entrypoint python bot -m igngbot_v4.migrate
docker compose --env-file .env --env-file .env.v4 -f docker-compose.yml -f docker-compose.v4.yml up -d --wait --wait-timeout 180 --no-build bot yunying
```

构建和启用仍沿用现役模型网关/allowlist/secret，不在工作区写入真实配置。正常升级只应用003/004：机械记录状态/重试/命令结果、定向呼叫授权字段和 recording 索引，回填既有已处理 ingress。23张表不变；001/002 checksum不变。没有 DROP/DELETE/TRUNCATE、附件搬迁、数据卷重建或数据库清理。
